# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/), and the project uses semantic
versioning once tagged.

## [Unreleased]

### Added
- In-container scheduler (`manage.py run_scheduler`) with minute and daily jobs,
  plus `prune_history` retention.
- Machine scheduler endpoint `POST /api/admin/scheduler/{job}` authenticated by
  `X-Scheduler-Token`.
- Hardened admin: superuser + TOTP (`OTPAdminSite`), login lockout, optional IP
  allow-list, environment-gated path, secure short sessions.
- Moderation CLI (`manage.py moderate`) and `debug_proxy` diagnostics.
- Render blueprint, Vercel proxy config, `.dockerignore`, SMTP settings,
  deployment/security/runbook docs and ADRs.
- Pyright is now clean (0 errors) and blocking in CI; the toolchain is pinned
  (`pyright`, `django-stubs`, `ruff`) and the temporary error-budget ratchet was
  removed. A Docker build + `/api/health` smoke test runs in CI.
- Dependencies are pinned through `backend/constraints.txt` (generated by
  `scripts/gen_constraints.py`) and used by CI and the Docker image.
- SEO basics for the SPA: per-route `<title>`/description/**canonical**/`og:url`
  with `noindex` on authenticated and credential pages, Open Graph + Twitter
  cards backed by a generated 1200×630 `og.png`, JSON-LD, and `robots.txt` +
  `sitemap.xml` generated from `VITE_SITE_URL` by `scripts/gen-seo.mjs` in
  `prebuild`.

### Changed
- Admin job triggers now require superuser; staff retains moderation API access.
- Rate-limit identity uses trusted-proxy-aware client IP and hop count.
- Health endpoint no longer exposes failure details in production.
- Paid plan prices and labels come from one SPA catalogue
  (`frontend/src/utils/plans.js`); the paid cards show their price with a
  **Coming soon** chip and a disabled call to action until the Polar products
  are approved, and are enabled per plan by flipping `comingSoon`. No price is
  duplicated in the app, and the README no longer repeats prices.
- Checkout is covered by backend tests: an unconfigured Polar product returns 400
  without calling Polar, and a missing API token returns 503.
- The unused `npm run test:unit` script was removed — the SPA has no unit tests;
  CI keeps lint + build for the frontend.

### Fixed
- The landing page's "Most Popular" badge is no longer cut by the featured
  pricing card's outline in dark mode: the pill straddles the border, and the
  translucent `--color-primary-soft` let the border show through it. The badge
  now paints an opaque base first.
- CI test failures caused by the short development `SECRET_KEY`: the fallback is
  now long enough for PyJWT (HS256) and Django, production refuses weak keys at
  boot, and PyJWT is pinned.
- OTP tests no longer depend on django-otp's wall-clock verification throttle;
  abuse/login counters are cleared between tests, and expected negative-path
  logs are captured with `assertLogs` instead of flooding the CI output.
- Notification webhook/Slack/Discord channels validate against SSRF at create
  and dispatch time.
- Unbounded growth of check history, abuse events, audit rows and the outbox.
- Refresh no longer shares the 5/min login bucket behind a shared proxy IP.
- Email notification channels are restricted to the account address.

### Security
- Permissions-Policy and SPA security headers added.
- OpenAPI docs disabled when `DEBUG=False`.
- Per-username login lockout independent of IP.

## [0.1.0] - initial development snapshot
- Uptime, keyword, domain-expiry, TLS and broken-link monitoring; status pages;
  Polar billing; 2FA; audit log; notification outbox; mobile/light-dark landing.
